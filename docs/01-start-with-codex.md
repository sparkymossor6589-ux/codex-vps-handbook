# 准备与 Codex 协作

项目从个人网络需求开始，后续才逐步增加分流、在线更新和应用去广告。开始时把范围写清，可以让后续改动围绕实际使用展开。

## 先写自己的需求

| 要交代的信息 | 示例 |
|---|---|
| 使用设备 | Mac、iPhone；另有安卓设备以后接入 |
| 常用业务 | ChatGPT、国内应用、音乐和 Steam |
| 网络环境 | 家庭 Wi-Fi、手机蜂窝，需要分别验证 |
| 预算 | 可接受的月度费用，以及超额流量的处理方式 |
| 维护目标 | 后续使用固定入口更新，保留回退材料 |
| 现有约束 | 保留已可用的节点、DNS 和分流，按需修补 |

价格、套餐和优惠会变化。项目中的历史配置使用过每月 5 美元基础套餐，这只是当时记录；购买时查看自己账户中的实际报价和账单。

## 建立本地工作目录

```text
我的VPS工作目录/
├── public/        # 教程、示例和准备公开的代码
└── private/       # 登录信息、实际配置、备份及验证原件
```

`private/` 留在自己设备中。不要为了让 Codex“看到所有信息”而把密钥、完整订阅地址或客户端数据库上传到公开仓库。

本仓库的 `.gitignore` 已覆盖常见私密材料，但它不能替代内容检查，也不能移除已经进入提交历史的文件。

## 如何分配工作

你负责说明使用现象、确认账户操作，并在真实设备上完成测试。Codex 根据可用权限检查文件、生成配置、修改维护程序并记录结果。设备界面、联网权限和可访问工具可能不同，教程中的工作应按当前环境执行。

每次把任务描述成以下四项：

1. **目标**：希望哪个行为发生变化。
2. **上下文**：设备、版本、当前配置和复现过程。
3. **约束**：必须保留哪些已有行为。
4. **验证**：怎样证明改动有效，以及怎样回退。

这种写法与 [OpenAI 官方 Codex 提示词文档](https://learn.chatgpt.com/docs/prompting#prompting-codex)中的目标、上下文、约束和验证组织方式一致。

## 本项目采用的记录习惯

每轮修改记录日期、目标、改动文件、采用来源、检查结果、待验证项目和回退方法。旧记录中“恢复旧版”可能只是当时测试的结束状态；判断当前版本时查看时间较晚、证据完整的记录。

公开教程重建的是这些记录能够支持的过程。提示词以可复用示例呈现，没有证据的历史对话细节不补写成原话。
