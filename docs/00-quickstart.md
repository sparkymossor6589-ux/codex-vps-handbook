# 从这里开始

这份手册按“先连通、再分流、再方便维护、最后加入去广告”的顺序组织。每一步都有输入、操作和完成条件，可以按自己的现状开始。

## 选择阅读路线

| 你的现状 | 建议路线 |
|---|---|
| 还没有服务器 | 准备 → 搭建 → 基础连接 → 分流 |
| 已有可用服务器 | 记录现状 → 分流 → 多设备接入 → 在线更新 |
| 基础连接正常，只想处理广告 | 去广告 → 单个应用检查 → 正常功能回归 |
| 想了解怎样用 Codex 做完这个项目 | 项目经过 → 提示词 → 对照各阶段教程 |
| 想读维护代码 | src/README.md → 本地回归检查 → 结合自己的环境改造 |

## 开始前准备

- 一份明确的需求：设备、网络环境、常用应用、预算和希望解决的问题。
- 自己可以管理的服务器账户与登录方式；购买、付费及账户验证由本人完成。
- 当前配置与一条可用的回退路径。已有连接时先保存备份，再开始修改。
- 一个独立的私人目录，用来保存真实参数；公开仓库只保留示例。

可以在 Codex 中打开本仓库，先粘贴以下**示例提示词**：

```text
请先阅读 README.md、docs/09-validation.md 和与我目标相关的教程。
我使用的设备和系统是：[填写]。
现有服务器/客户端状态是：[填写]。
本次只想完成：[一个可检查的目标]。
请先检查已有环境与备份，说明必要改动和回退方式；
完成后分别报告配置检查、客户端检查和我需要在设备上验证的内容。
不要把真实连接信息写入公开文件或聊天输出。
```

## 每一步什么时候算完成

1. **基础连接**：服务器服务正常；客户端选择正确节点；目标访问实际成功。
2. **分流**：国内与目标海外域名分别命中预期策略；日常应用能用。
3. **在线更新**：远端文件回读一致；客户端更新后实际选中并使用新版。
4. **去广告**：模块、设备证书和处理链路有效；目标广告现象改变；正常功能通过检查。

如果只有文件生成或网页返回 200，请把记录停在对应层级。可以继续排查，不提前填写“手机已完成”。
