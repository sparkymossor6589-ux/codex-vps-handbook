# 可复用的 Codex 提示词

以下内容根据项目步骤重新编写，均为**示例提示词，不是历史聊天原文**。方括号填写自己的环境；真实凭据通过本地私人文件管理。

## 1. 把需求整理成方案

```text
我想搭建一台由自己管理的 VPS，用于：[填写]。
设备：[填写]；网络：[填写]；预算：[填写]。
请结合我的位置、实际业务、费用与后续维护比较合适方案，注明信息日期和来源。
先给出可核对的方案，以及购买后需要检查的配置。
将选型、账户操作、服务器部署和设备验收分开记录。
```

## 2. 部署基础连接

```text
按已选方案检查这台新服务器，先确认系统、架构、端口和已有服务。
为部署保存来源、版本、校验值和回退材料。
连接凭据在服务器生成并保存在私人文件，不输出到公开文档。
完成后检查配置和服务，给出对应客户端的导入方式及真实业务验收步骤。
```

## 3. 改进分流

```text
现有节点已经能用，本次目标是：[填写具体应用和预期路径]。
先读取现有配置、检查顺序和已有例外，保存执行前备份。
只增加有来源或实际请求依据的规则，说明范围与可能影响。
验证目标域名的客户端实际命中，并检查原有常用业务仍然正常。
```

## 4. 建立在线更新

```text
请把节点订阅与分流配置的更新入口整理清楚。
使用自己的私人 HTTPS 服务和稳定地址，保留版本化文件与回退点。
页面应告诉使用者按什么顺序导入，不混淆网页、订阅与配置。
发布后回读核对文件，再记录每台设备是否实际刷新并使用了新版。
```

## 5. 排查具体故障

```text
设备与版本：[填写]。
网络：[Wi-Fi/蜂窝]。
现象和复现步骤：[填写]。
对照现象：[例如关闭连接后是否恢复]。
请先检查已有配置和能获得的请求证据，区分已知事实与推测。
按最小范围修改，分别验证发布、规则命中和实际业务，并提供回退方式。
```

## 6. Steam 分流

```text
我希望 Steam 商店、社区和社区图片走指定节点，游戏下载与更新使用本地出口。
请先检查真实内容服务器与更新地址的来源，再设计规则顺序。
避免对所有共享 CDN 做一刀切处理。
先确认客户端命中，再单独验证真实下载；没有下载测试时保留待测状态。
```

## 7. 研究应用去广告

```text
基础节点与分流已可用，这次只增加：[填写应用]的去广告能力。
先阅读规则及实际依赖，记录来源、版本、许可和兼容性。
使用独立模块，列明主机、脚本和附带功能，不把未知功能自动视为需要启用。
需要 HTTPS 解密时，说明本设备证书设置与停用办法。
先测一款应用，检查广告变化和搜索、播放、消息等正常功能。
```

## 8. 知乎开屏仍存在

```text
模块、HTTPS 解密和证书信任的当前状态：[填写]。
请先验证目标请求是否实际经过处理链路，检查协议、命中与响应。
每次只改变一个可比较的条件；如考虑 UDP/443 定向实验，说明影响范围与回退。
不要把第三方个别用户报告直接认定为我的设备根因。
```

## 9. 维护与整理

```text
请盘点本次更新前后的状态、备份、来源和验证记录。
保留当前交付、维护源码、回退及待接入材料。
清理限定在：[填写目录]，先列清单并采用可恢复方式。
最后分别报告文件整理、服务器状态、客户端状态和仍待我确认的设备项目。
```

## 10. 准备公开版本

```text
请另建公开副本，保留原项目。
把教程、无凭据示例、适合公开的源码与第三方来源整理成独立目录。
排除密钥、节点凭据、订阅地址、二维码、客户端数据库、原始日志和私密备份。
根据已知私人值和常见模式检查公开文件，再检查压缩包与文档链接。
先交付本地审阅版，不创建远端仓库或上传。
```
