# 从搭建到维护的过程

| 阶段 | 需求与做法 | 留下的结果 |
|---|---|---|
| 选型 | 把预算、地区、设备和业务交给 Codex，比较有日期和来源的方案 | 选择 Lightsail 东京；前期 Windows 方案不等于实际交付 |
| 搭建 | Ubuntu 部署固定版本 Xray，核对哈希、配置与服务，再导入 Mac | 基础连接可用 |
| 分流 | 国内 / 局域网直连，目标业务走节点，检查客户端命中 | 保留原节点，小范围修补音乐和 Steam |
| 多设备与在线维护 | 从传文件改为私人 HTTPS 入口，分开导入节点与分流；资源按版本保存 | iPhone 两种网络文字对话获确认；安卓入口完成、真机待测 |
| 应用去广告 | 阅读第三方模块与依赖，独立管理证书、模块和回退 | 形成 14 应用整合，继续逐设备检查 |
| 排查与兼容性 | r3 → r25 逐步检查运行引擎、空回包、推荐流字段及实际处理链路 | 有局部成功，也有回归和广告复现；最新手机效果待验收 |
| 视频分流 v5 | 对照真实媒体与实际出口，只保留通过的精确 Dailymotion 主机 | Mac 两个样本通过，其他试验撤回或保留原策略 |

整个过程由用户提出需求、选择方案和确认实际使用，Codex 辅助检查、实现和整理。可复用的工作方式是：**明确小目标 → 保留基线 → 按证据修改 → 分开验收 → 留回退点**。
