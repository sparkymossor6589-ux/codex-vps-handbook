# 应用广告排查

当前模块为 **20261025-r39**。Mac 已更新，手机阅读与广告效果仍待确认。

## 最近改动

- **r37 阅读修复**：为知乎请求白名单补回回答、下一页渲染、图片配置等路径。回放恢复了 15 条正常请求，商业请求仍被拦截；手机实际阅读尚待确认。
- **r38 传输试验**：对一个已观察到的目标仅拒绝 UDP/443，保留 TCP，未取得独立的 UDP 命中验证。
- **r39 裸 IP 试验**：改为三个目标的全端口 TCP/UDP 拒绝，并设置 `no-resolve`，不为匹配主动解析域名。Mac TCP CONNECT 对照为 200 → 本地 404；图片配置接口返回 200，B 站视频小段仍可读取。

**已知风险**：这些地址也可能承载正常业务。同址的普通裸 IP 请求会被拒绝，手机评论、阅读和图片需要一起检查。出现异常时停用新增规则，或恢复自己验证可用的版本；服务端回退后仍需更新客户端。

## 发布后复核

手机记录可确认部分广告域名拦截，但未取得 r39 加载回执、新裸 IP 拒绝命中或界面验收。裸 IP 通道在发布前已未出现，不能把之后的缺失算作新规则效果。阅读和评论请求仍有记录，实际显示待确认。

## 前面的排查留下了什么

| 阶段 | 结果 |
|---|---|
| r3 → r16 | 修补运行引擎、空回包和开屏数组处理；手机出现过局部有效反馈，也出现脚本已执行但仍显示广告的情况 |
| r18 → r27 | 检查素材入口、推荐流字段、B 站搜索和闲鱼恢复路径；r26 已确认更新后仍有全屏广告 |
| r28 → r30 | 共享 IP 整地址拒绝存在误伤机制，r30 撤销五条规则；连接恢复不等于手机评论恢复 |
| r31 → r34 | 撤回接管试验，恢复原有功能，再补公开广告规则与 QQ 候选入口 |
| r35 → r39 | 整合知乎严格请求策略，修复阅读路径遗漏，继续验证裸 IP 通道 |
