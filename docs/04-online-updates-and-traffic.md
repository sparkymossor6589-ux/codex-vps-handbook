# 在线更新与流量估算

多设备接入后，反复传文件容易让设备停在不同版本。项目逐步加入私人 HTTPS 入口、稳定配置地址和版本化资源，使更新有明确入口与回退点。

## 接入服务的职责

接入服务提供节点订阅、分流配置、安卓接入页面和应用模块资源。连接服务继续由 Xray 承担；发布普通规则更新通常不需要重建节点。

公开参考源码位于 [src/](../src/README.md)。它读取自己的配置、授权表和文件；仓库中的示例不包含可用服务地址。

## 一次更新的流程

1. 保存当前版本与检查记录。
2. 在本地生成新文件，比较改动范围。
3. 检查语法、目标规则及资源依赖。
4. 发布到自己的私人服务，回读文件并核对内容或哈希。
5. 在设备上刷新相应的配置、订阅或模块。
6. 确认实际使用新版，再测试目标业务与原有常用业务。

分流配置、节点订阅与应用模块分别更新。只刷新节点订阅，不代表分流与模块已更新。后台调度也不能当作立即生效的保证，需要立即应用时手动刷新并检查。

## 稳定地址与固定资源

可以让用户入口和主配置地址保持稳定，把具体资源保存在有版本的目录中。资源清单列出允许分发的文件及 SHA-256，发布时切换当前版本指针，出现问题时切回上一版。

本项目的去广告整合曾回读核对 37 个模块与依赖文件。这个数字代表交付文件，不能解释为 37 款应用或 37 项设备效果测试。

## 私人地址仍需保护

实际接入地址含有授权令牌，持有完整地址的人可能获得连接信息。网页、二维码、浏览器历史、分享链接和截图都可能包含它。公开项目只保留示例地址，不公开自己的私人入口。

源码默认拒绝公开明文 HTTP 监听；回环地址用于本机测试，公开访问需要配置 TLS。部署时还要核对域名、证书、服务用户、端口、防火墙和文件权限。参考源码不负责自动完成这些环境设置。

## 估算流量怎样理解

项目读取服务器主网卡的接收与发送字节数，累计后显示一个月度估算。它不是 AWS 账单接口，包含整台服务器上的相关流量与转发两侧，不能把数值直接认定为自己应付的账单。

公开源码保留历史计数算法：首次采样会纳入本次系统启动以来的网卡计数。该做法在原实例有启动时间核对的前提下采用；迁移到运行已久或跨月启动的机器时，应先调整初始化口径。采样跨月时，间隔内新增量记入采样到的月份，属于估算。

月度展示按 UTC 月初重置，对应北京时间当月 1 日 08:00。配额是本地配置项。云服务的流量计费以官方口径和实际账单为准，参见 [Lightsail 流量说明](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-faq-data-transfer-allowance.html)。

## 常见误解

| 观察到的结果 | 能支持的结论 |
|---|---|
| HTTPS 下载返回 200 | 资源可获取，还需校验内容与设备使用情况 |
| 回读哈希一致 | 发布内容一致，还需客户端更新 |
| 网页入口已停用 | 后续下载可能被阻止；已导入节点是否失效需另行处理 |
| 估算流量减少 | 本地计数发生变化，不能替代云账单 |
