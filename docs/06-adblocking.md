# 应用去广告：从独立模块到知乎开屏排查

项目在基础分流稳定之后加入应用增强。去广告模块、连接节点和主分流分别管理，便于确定新增功能的影响和回退范围。

## 实际整合范围

首批主清单包含知乎、小红书、哔哩哔哩、百度贴吧、微博、Keep、高德地图、菜鸟、闲鱼、网易云音乐、什么值得买、喜马拉雅、12306 和起点。

“纳入整合”说明为该应用选择了来源并整理模块，不等于当前版本全部功能通过验收。来源索引见 [upstream-apps.json](../data/upstream-apps.json)。

部分上游模块包含界面精简或其他附带功能，采用前应阅读具体处理内容和开关。公开版本没有把这些第三方脚本、规则正文或运行依赖重新打包；读者按来源许可和当前客户端重新审查。

### 这些功能的作者

应用规则和脚本属于 fmz200、ddgksf2013、app2smile、Biliverse、zmqcherish、blackmatrix7 等对应作者。本项目做来源选择、格式适配、冲突处理与交付维护；转换和托管不改变原代码归属。具体许可状态见 [署名总表](../THIRD_PARTY_NOTICES.md)，许可未明确的来源不作再分发保证。

## 第一步：阅读来源和依赖

对每个来源记录仓库、文件路径、获取版本、哈希、目标客户端和许可情况。区分只看到项目介绍、读过规则、读过依赖源码，以及在设备上实际运行过。

原项目将动态依赖整理为固定版本资源：整合了 14 款应用的选定模块，归档 21 个不同 JavaScript 依赖，并记录资源清单。脚本解析通过只说明语法层检查完成，不代表在客户端触发和处理结果都正确。

## 第二步：把去广告作为独立模块

可以采用一个总模块，或按应用启用独立模块；同一应用不要重复开启总模块与对应独立模块。

整合时需要检查重复规则、脚本标签、主机覆盖和请求匹配冲突。原项目去除了 8 条完全重复项，并为共享主机上的特定处理增加排除条件。选定样例未发现重复触发，仍不能认为覆盖了所有真实请求。

公开的 [模块示例](../examples/adblock-module.srmodule.example)只包含一个保留域名上的示意拒绝规则，没有可用广告脚本、MITM 主机清单或证书。它用于展示独立模块形式，不是原 14 款应用的可用替代品。

## 第三步：需要 HTTPS 处理时，在本机设置证书

先保持模块关闭，阅读目标客户端当前版本的 HTTPS 解密说明。需要时在自己的设备生成 CA，按系统要求安装并明确授予信任，再启用相关设置与模块。

每台设备独立生成自己的 CA；CA 私钥、导出的 P12/PFX 和密码留在自己设备上。公开仓库不提供可供所有人共同使用的根证书。

iPhone 手动安装证书描述文件后，还需要在系统证书信任设置中确认 SSL 信任。Mac 可以通过客户端原生导出公共证书，再在钥匙串中设置适当信任。若遇到证书错误，先检查实际签发者、有效期、信任与应用行为，不跳过验证来制造成功结果。参见 [Apple 关于手动安装证书信任的说明](https://support.apple.com/en-us/102390)。

HTTPS 解密覆盖的是列出的主机，同主机的正常请求也可能被处理。仅按需要启用，并检查登录、搜索、播放、消息等原有功能。

## 第四步：先测一个应用

1. 确认模块版本、启用状态、证书信任和解密设置。
2. 从后台退出应用，再重新打开，记录广告表现。
3. 查看对应请求的协议、规则命中和处理结果。
4. 暂停模块做一次对照，再恢复目标状态。
5. 分别检查 Wi-Fi / 蜂窝，以及该应用的主要正常功能。

开始时保留缓存条件，便于判断单次改动的影响；需要清缓存时另记为一个变量。

## 知乎开屏的 r2 → r3 过程

r2 完成模块整合与依赖交付，但手机随后反馈仍有开屏广告。用户确认了开关和信任设置，这仍缺少请求实际走过处理链路的证明。

r3 增加了一条定向实验：

```text
AND,((DOMAIN,api.zhihu.com),(PROTOCOL,UDP),(DST-PORT,443)),REJECT-NO-DROP
```

这是原项目 Shadowrocket 环境中的规则形式，不可直接视为 Mihomo 语法。它只针对该主机的 UDP/443，但也会影响该主机上的普通请求；是否能回退 TCP 与实际客户端及服务有关。

改动后回读了 37 个模块和依赖资源，检查主体配置、节点订阅与服务状态保持。后续用户确认手机知乎彻底退出后冷启动无开屏，但新增反馈显示熄屏 / 亮屏回前台仍弹广告，尚未完全解决。这个结果是设备使用反馈，不把它扩展为所有设备、所有版本的承诺，也不把多项设置后的变化当作单一原因的证明。

## Mac 上怎样单独验证

Mac 另行生成并信任本机 CA，启用模块和 HTTPS 解密；随后对知乎开屏接口做模块关闭与开启的对照。记录显示响应经过本机 CA，启用后接口返回内容与来源响应头发生变化，同时基础联网正常。

这证明了选定接口在本机被处理。实际返回是空体，不能声称已经精确验收成模块声明的 `{}`。Mac 上 14 款应用的逐项效果仍未完成，不能借用手机的结果填上。

## 回退

先停用新增模块，观察目标问题和基础联网。若 HTTPS 解密只为本次设置，可按需要关闭其总开关；证书信任和证书本身由对应设备单独管理。

服务端需要回退资源时切回前一版本。回退文件不会自动撤销已安装在设备上的证书，也不需要因此覆盖节点或流量累计状态。
