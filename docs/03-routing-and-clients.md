# 分流与多设备接入

基础连接可用后，项目开始处理国内应用、局域网和不同设备的接入方式。规则能被加载只是起点，还要检查实际命中与业务表现。

## 先分清三个对象

| 对象 | 负责什么 | 更新后应检查什么 |
|---|---|---|
| 节点订阅 | 连接参数、节点名称，以及附带的估算流量信息 | 节点是否存在、参数是否正确 |
| 分流配置 | DNS、策略组和访问规则 | 当前使用标记、规则解析与命中 |
| 接入网页 | 引导安装、导入和更新 | 按钮是否指向正确资源 |

接入网页地址通常不能直接填入节点订阅栏。项目在手机页面按顺序提供了节点订阅与在线配置的导入操作。

## Mac 与 iPhone

实际项目使用 Shadowrocket 的配置路由模式，并让固定策略组选择指定节点。规则的顺序大致为：

1. 局域网、本机及保留地址。
2. 有明确需求的个人例外，如音乐和 Steam 下载。
3. 指定服务及必要依赖。
4. 公共国内外规则与国内地址兜底。
5. 最终策略。

具体规则必须检查“较窄的例外是否排在较宽的域名后缀前面”。例如某个下载子域需要直连，就应先于整站代理后缀生效。

公开的 [Shadowrocket 示例](../examples/shadowrocket.conf.example)是简化配置，使用 `My VPS` 节点名和 `VPS` 策略组，展示主要结构；不等同于项目中经过多轮补丁的完整生产配置。

导入时先备份，然后确认节点名称与策略组绑定一致。客户端中可能同时存在“默认配置”和“正在使用”的标记，更新文件后要核对实际使用状态。

## Android 与 Mihomo

安卓配置按 Mihomo 支持的字段生成，不能把另一客户端的规则原样视为兼容。公开 [Mihomo 示例](../examples/mihomo.yaml.example)展示节点字段和少量规则，未附带生产环境的完整 DNS 策略与规则集。字段含义参见 [Mihomo VLESS 官方文档](https://wiki.metacubex.one/config/proxies/vless/)。

实际项目经历过独立入口与统一交付两种模式，最终整理为一份通用配置和统一页面，兼容部分旧入口。公开源码保留这类入口处理能力，真实授权表和安装包不分发。

截至记录日期，安卓端有入口、配置交付及内核解析检查，仍缺少安卓真机导入、目标业务和 Wi-Fi / 蜂窝切换验收。iPad、另一台 Mac 与 Windows 也不能直接沿用其他设备的完成状态。

## 怎样检查分流

选择几个有代表性的业务域名，在客户端查看实际命中规则和最终策略，再进行相应业务操作。

本项目曾通过截图核对 ChatGPT 域名走指定节点、WPS 资源域名直连；腾讯会议网络自检也有记录。这些检查不能代替会议双向音视频、登录后业务或实际打印测试。

每次更新后保留：设备、客户端版本、配置版本、规则命中、业务结果及待测内容。
